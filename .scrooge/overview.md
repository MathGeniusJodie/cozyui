Cozyui is a pixel-art desktop environment for Linux/X11 that bundles a terminal emulator, todo list, AI chat, prize wheel, radio alarm clock, battery indicator, calendar, budget countdown, weekly stats, and a meal-timer hunger bar into a single framebuffer-rendered application.

The architecture centers on a 16-color indexed palette loaded from `na16-1x.png` whose `Index` values flow through a pipeline: each widget owns a sub-framebuffer composited onto the root framebuffer at dynamically computed positions, then a precomputed `PresentLut` converts indices to BGRA for shared-memory presentation to X11. `Paint::Checker` dithering for the background is anchored to destination coordinates so overlapping widgets mesh seamlessly, and `Graphics::Swap` allows per-draw index remapping for tints and silhouettes. The desktop background sprite (`desk.png`) is stretched horizontally via a tri-panel mapping to fill any window width. A shared `expand_tilde` helper in `src/paths.rs` converts `~/` prefixes to `$HOME` for any widget that needs home-relative paths. Layout is fully dynamic: `sync_dynamic_layout` recomputes all widget positions on every frame, and the window resizes to match whenever any widget's dimensions change. The ten widgets—Puter (alacritty terminal), Toodle (todo), Fwends (AI chat via OpenRouter), Twirl (prize wheel), Wavey (radio alarm clock via mpv/IPC), Fizzle (battery candle), Day (calendar), Budgit (budget countdown), Stats (weekly completion bar graph), and Hunger (meal-timer countdown)—are dispatched by a `WidgetId` enum whose `ALL` array must stay manually synchronized with the `WIDGET_COUNT` constant (currently 10). Fwends supports four switchable AI models with a thinking-mode toggle that selects between a fast model and a beefier reasoning model in a single direct OpenRouter request, enabling high-effort reasoning when the lamp is on; the former two-model senpai briefing pipeline has been removed. Budgit reads a dated expense config (`budgit.conf`) and ledger CSV (`budgit.csv`) to display a live "money left" countdown with color-coded urgency, using piecewise period-based burn rates; it also scans template folders (via `rg`) to estimate completed SVGs, crediting each at a configurable `dollars per svg` rate (default `100$`, set in `budgit.conf`), which is folded directly into the balance rather than shown as a separate stat row. The SVG count runs on a background thread (`spawn_svg_counter`) that computes the per-finished-SVG `<path>` average once via `avg_paths_per_svg(DONE_DIR)`, then periodically (every `SVG_REFRESH` = 1 s) scans the in-progress `TEMPLATES_DIR`, sending estimates over an `mpsc` channel that the render thread drains without blocking. The SVG credit (`dollars_per_svg * svgs_completed`) is added to `start_balance` in `compute_view` so completed SVG work directly increases the "money left" display. Budgit shows four stat rows: Monthly, Daily, Days left, and estimated SVGs completed. Stats reads completed-todo files via `toodle::done_file_path` (which resolves paths through the shared configurable `toodle_root()`) and renders a 7-day bar chart with priority-colored segments (urgent=crimson, frog=green, normal=orange, snail=blue), refreshing every 2 seconds, and is positioned directly beneath Budgit in the top-left column. Toodle's file storage is driven by a configurable root directory read from `toodle.conf` (defaulting to `~/Desktop/RemoteVault/✅ Toodle/`), with `done_dir()`, `done_file_path()`, and path helpers shared with Stats via `pub` access; `toodle_root()` resolves the path once via `OnceLock` and `expand_tilde` handles `~` expansion. Toodle's backing files use standard markdown checkbox format (`- [x]`/`- [ ]`), with archived done files written as `.md`; the `TodoItem` struct carries an `is_checkbox` flag so plain text lines (headings, notes) are kept verbatim without rendering a checkbox glyph, and the dice-roll highlight skips non-checkbox lines. Per-section page counts are capped at `MAX_PAGES_PER_SECTION` (4) so overflow pages are simply not navigable. The static page-stack art (shadows, page images, checkboxes) is cached and only rebuilt when the stack geometry changes, with live front-page text, checks, and cursor painted on top each frame. Archive operations use staged atomic writes with a transaction marker for crash recovery. Twirl persists a running total of all awarded points to `~/Desktop/RemoteVault/frogpoints.md` (with tilde expansion via `crate::paths::expand_tilde`) and awards a random segment's value before starting a fresh spin when re-triggered mid-spin, preventing players from timing re-spins to pick a result. Hunger displays a row of five apple sprites that deplete through four bite-level states (100%, 75%, 50%, 25%) as the next mealtime approaches, with a countdown label underneath; five meals are evenly spaced across a 7:00 AM–8:00 PM local-time window, the last-eaten meal time persists in `hunger.txt`, and clicking when empty ("EAT!") refills the bar to count down to the following meal. Hunger uses a transparent fill color and sits in the bottom padding directly below Puter, horizontally centered, overlapping Puter's lower edge by `HUNGER_PUTER_OVERLAP` (40 px) without consuming layout space.
